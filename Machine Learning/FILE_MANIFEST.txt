LAB 7: MODEL EVALUATION (12 KB)
-------------------------------

Lab7_README.md
  - Beyond accuracy: Why it's misleading
  - Confusion Matrix:
    * True Positives, True Negatives, False Positives, False Negatives
    * Visual representation of model performance
  - Key Metrics:
    * Precision: Of predicted positives, how many are correct?
    * Recall: Of actual positives, how many did we find?
    * F1-Score: Balanced metric (harmonic mean)
    * AUC-ROC: Ranking ability
  - Cross-Validation:
    * K-fold validation for robust estimates
    * Addressing data scarcity
    * Getting reliable performance estimates
  - Metric Selection:
    * Medical diagnosis: High recall (don't miss cases)
    * Spam detection: High precision (avoid false alarms)
    * Fraud detection: Balance both
  - Key insight: Different domains prioritize different metrics
  - Technologies: scikit-learn metrics, cross_val_score
  - Real-world: Model selection and threshold tuning

LAB 8: BIAS-VARIANCE TRADEOFF (11 KB)
-------------------------------------

Lab8_README.md
  - Central concept: Every model faces this tension
  - Underfitting:
    * Model too simple
    * High bias, low variance
    * Ignores patterns in data
    * Solution: More complex model
  - Overfitting:
    * Model too complex
    * Low bias, high variance
    * Memorizes noise instead of learning patterns
    * Solution: Regularization and validation
  - Regularization Techniques:
    * L1 (Lasso): Sparse feature selection
    * L2 (Ridge): Smooth penalty
    * Elastic Net: Combination of L1 and L2
  - Train/Test Gap:
    * Reveals overfitting
    * Cross-validation for robust estimates
  - Key insight: Generalization > Accuracy; regularization essential
  - Technologies: LinearRegression, Ridge, Lasso, cross_val_score
  - Real-world: Production models must generalize; overfitting = poor deployment performance

LAB 9: ENSEMBLE METHODS (11 KB)
-------------------------------

Lab9_README.md
  - Why ensembles work: Diversity + Accuracy
  - Random Forests:
    * Ensemble of decision trees
    * Bagging: Bootstrap sampling
    * Feature randomness at each split
    * Feature importance
  - Gradient Boosting:
    * Sequential model improvement
    * Each tree corrects previous errors
    * XGBoost, LightGBM, CatBoost implementations
  - Voting Classifiers:
    * Hard voting: Majority rule
    * Soft voting: Average probabilities
    * Combines diverse algorithms
  - Bagging vs Boosting:
    * Bagging: Parallel, reduces variance
    * Boosting: Sequential, reduces bias
  - Key insight: Ensemble > Individual; diversity matters
  - Technologies: RandomForest, GradientBoosting, VotingClassifier
  - Real-world: Kaggle winners use ensembles; production systems stack models

LAB 11: HYPERPARAMETER TUNING & AUTOML (12 KB)
----------------------------------------------

Lab11_README.md
  - Model performance heavily influenced by hyperparameters
  - GridSearchCV:
    * Exhaustive search over parameter grid
    * All combinations evaluated
    * Computationally expensive but thorough
    * Best for small grids
  - RandomSearchCV:
    * Random sampling of parameter space
    * More efficient than grid search
    * Works well with large spaces
    * Often finds good solutions faster
  - Automated Machine Learning (AutoML):
    * AutoGluon: Automated model selection
    * Handles preprocessing, feature engineering, model selection, ensemble
    * Dramatically reduces human effort
    * Competitive with manually-tuned models
  - Hyperparameter Importance:
    * Learning rate, regularization, tree depth, number of estimators
    * Model-specific vs general hyperparameters
    * Sensitivity analysis
  - Key insight: AutoML democratizes ML; good solutions without experts
  - Technologies: GridSearchCV, RandomSearchCV, AutoGluon
  - Real-world: AutoML enables rapid prototyping and baseline models

LAB 12: ETHICS, FAIRNESS & BIAS IN ML (11 KB)
---------------------------------------------

Lab12_README.md
  - Critical topic: Building fair, responsible ML systems
  - Bias Sources:
    * Representation bias: Data doesn't represent all groups
    * Measurement bias: How outcomes are measured
    * Aggregation bias: Treating diverse groups as monolithic
    * Evaluation bias: Metrics not appropriate for all groups
  - Fairness Metrics:
    * Demographic parity: Equal positive rates across groups
    * Equalized odds: Equal TPR and FPR across groups
    * Calibration: Predicted probability matches actual probability
    * Individual fairness: Similar individuals treated similarly
  - Bias Detection:
    * Performance disparity across groups
    * Confusion matrix analysis by subgroup
    * Statistical tests for discrimination
  - Responsible AI Practices:
    * Transparency: Explain decisions to stakeholders
    * Accountability: Audit trail and human oversight
    * Fairness: Measure and mitigate bias
    * Privacy: Protect sensitive data
  - Real-World Implications:
    * Hiring systems: Gender/race bias in candidate screening
    * Loan approvals: Discriminatory lending practices
    * Criminal justice: Racial bias in risk assessment
    * Healthcare: Equitable care across populations
  - Key insight: Ethical AI is non-negotiable; measurement mandatory
  - Technologies: Statistical tests, fairness libraries, bias detection
  - Real-world: Regulatory requirements (GDPR, CCPA); ethical imperative
